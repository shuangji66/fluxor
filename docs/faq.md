# 常见问题解答 (FAQ)

本文汇总了在日常使用 Fluxor 面板过程中，用户经常遇到的问题及其排查与解决办法。

---

### 问题 1: 为什么打开内置的 `MetaCubeXD` / `Zashboard` 外部面板时，提示“无法连接”或需要输入 Host/Secret？
**排查与解决方法**：
1. **外部控制密钥与端口配置**：
   * 外置面板需要通过外部控制器（External Controller）API 与内核通信。
   * 请前往「订阅配置」页面，确认「外部控制端口」和「面板连接密钥 (Secret)」设置正确，并点击底部的「保存并应用」按钮，确保配置已写入底层内核。
2. **手动输入信息**：
   * 如果面板没有自动填充，您可以手动在外部面板连接界面输入：
     * **Host/IP**：您面板的公网 IP、局域网 IP 或域名（非 `127.0.0.1`）。
     * **Port**：您设置的外部控制端口（默认为 `9090`）。
     * **Secret**：您在订阅设置中定义的密钥。

---

### 问题 2: 面板无法启动底层内核进程，提示启动失败？
**排查与解决方法**：
1. **检查执行权限**：确保内核二进制文件（默认 `/var/apps/Fluxor/target/bin/mihomo`）拥有可执行权限，可在终端执行 `chmod +x` 赋予权限。
2. **检查目录读写权限**：确保运行用户对内核工作目录（默认 `/var/apps/Fluxor/shares/Fluxor`，真实落点为 `/vol1/@appshare/Fluxor`）与运行数据目录（默认 `/var/apps/Fluxor/var`，日志就写在这里）拥有读写权限。
3. **查看日志**：
   * 面板自身的运行日志位于运行数据目录（`FLUXOR_DATA_DIR`）下的 `fluxor.log`（飞牛 OS 默认 `/var/apps/Fluxor/var/fluxor.log`），格式为「时间戳 + 等级 + 模块标记 + 英文正文」；
   * 内核自身的运行日志请在面板「日志」页面查看；
   * 常见原因是端口冲突或 `config.yaml` 语法错误。
4. **若是配置导致的失败**：订阅保存时的错误弹窗通常会指出是 `config.yaml` 的哪一行有问题，修正后重试即可。

### 问题 3: 更新订阅失败，提示“Get ... timeout”或解析出错？
**排查与解决方法**：
1. **核对链接与格式**：请确认订阅链接在浏览器中能正常打开，并且返回内容包含 `proxies:` 或 `proxy-providers:` 等标准的 Cl~a~sh 节点格式。
2. **了解超时上限**：订阅更新采用「直连 → 回退临时内核」两阶段，**每阶段限时 15 秒且不重试**。因此如果机场线路本身很慢，总耗时超过约 30 秒就会失败——这不是卡死，而是有意设定的上限。请确认机场可用性或更换网络环境。
3. **DNS 解析问题**：
   * 在「内核配置」页底部的「DNS 查询」中输入订阅域名并查询，看是否能解析出 IP。
   * 若无法解析，说明系统 DNS 配置有误，请将 DNS 改为公共 DNS（如 `223.5.5.5` 或 `119.29.29.29`）。
4. **目录不可写**：切换模式下请确保 `shares/Fluxor/proxies/` 目录可写。

### 问题 4: TProxy 透明网关富强开启后没有效果，设备无法正常富强？
**排查与解决方法**：
1. **系统环境支持**：TProxy 强依赖 Linux 的 nftables，请执行 `nft --version` 确认。
2. **权限是否充足**：下发规则需要 root 权限，权限不足时面板会返回失败并**自动回滚开关**（不会出现"界面显示已开启、实际规则没装上"的情况）。
3. **核对端口配置**：确认 TProxy 端口非 0（默认 7898）。端口为 0 时面板会直接拦截开启操作。
4. **本机是否要富强**：若需要面板主机自身的出站流量也走富强，请在「配置」→「透明代理」卡片中打开**「接管本机流量」**这一独立开关（注意：它不在绕过列表弹窗里，且启用 TProxy 期间不可修改）。
5. **检查绕过规则是否写错**：格式不合法的行会被跳过并在日志中记录原因。若某条绕过规则没能生效，先去日志确认它是否被判为无效。
6. **清理规则残留**：若透明富强偶发失效，可在「内核配置」页重启内核以重新下发 nftables 表。
7. **面板重启后开关会自动归零**：这是**预期行为**——nftables 规则不跨重启存活，面板启动时会清除残留规则并重置开关，以保证「面板显示的状态」与「系统实际状态」一致。

### 问题 5: 日志控制台、速度或内存监控显示一片空白？
**排查与解决方法**：
1. **检查内核运行状态**：这些监控依赖内核运行，请先确认内核已成功启动并处于「运行中」。
2. **排查 WebSocket 连接阻断**：
   * 实时流量、内存、日志与连接数据均通过 WebSocket 传输。
   * 若您通过 Nginx 反向代理访问面板，请确认站点配置包含了支持 WebSocket 的 `Upgrade` / `Connection` 头部转发规则。
   * 部分防广告/防追踪的浏览器扩展可能拦截 `ws` 协议请求，建议用无痕窗口排除干扰。
3. **日志流会自动重连**：日志断线后按 1s→30s 指数退避自动重连，若长时间空白说明连接始终建立失败，应排查第 2 条。

### 问题 6: 仪表盘上的流量趋势折线图显示一条直线，没有数据波动？
**排查与解决方法**：
1. 该图表需要内核正常运行才会产生数据，请先确认内核处于「运行中」。
2. 若确实有流量但图表不动，可尝试在「内核配置」页点击「清空 DNS 缓存」「清空 FakeIP 缓存」，并重启内核以重置统计。
3. 确认您使用的内核版本未被裁剪掉流量统计相关的接口。

---

### 问题 7: 为什么修改了面板参数或者订阅设置，内核却没有发生变化？
**排查与解决方法**：
* 在 Fluxor 中，修改订阅或参数后，**必须点击页面右上方的「保存并应用」按钮**。
* 点击后系统才会重新渲染生成最新的 `config.yaml`，并向内核发送配置热重载指令。仅修改输入框内容而不点击保存是不会生效的。
* 例外：部分**即时生效**的项（如内核常规参数、TProxy 高级设置里的「接管 IPv6 流量」、TUN 高级设置里的参数）在失焦/切换时立即保存，不需要点保存；其中 **TUN 参数只写 `tun.json`，下次开启 TUN 时生效**，弹窗中也会标明。
* 如果提示配置已生成但重载失败，请检查内核是否在运行；内核启动失败通常是 `config.yaml` 存在错误，订阅保存时的错误弹窗会指出具体行号。

### 问题 8: 部分国内网页加载缓慢或打不开，显示域名解析被污染？
**排查与解决方法**：
* **清空内核缓存**：通常是 DNS 缓存污染所致。前往「内核配置」页，在高级运维工具栏中分别点击「清空 DNS 缓存」与「清空 FakeIP 缓存」。
* **检查运行模式**：确认是否被设成了 Global（全局富强）或 Direct（直接连接）。若希望智能分流国内外站点，请切回 Rule（规则分流）模式。

---

### 问题 9: 内核崩溃或被外部结束后，面板还显示「运行中」吗？
**不会。** 面板的内核状态由后端**主动推送**：

* 内核若崩溃、被 `kill -9` 或 OOM，后端会立即感知并推送「已停止」，面板会同步显示为已停止状态，无需手动刷新页面。
* 这也意味着您**不需要**为了让状态刷新而反复刷新浏览器。
* 如果面板显示的运行状态与 `ps` 看到的实际情况不一致，请确认面板读到的 `core.pid` 与内核实际进程一致：该文件默认位于运行数据目录（`FLUXOR_DATA_DIR`）下，OpenWrt 下固定在 `/var/run/`；两个面板实例若共用了不同的 PID 路径，就会各看各的。

### 问题 10: 面板显示「版本未知」是怎么回事？
* 表示当前运行的 Fluxor 二进制**在编译时没有注入版本号**。自行用 `go build` 直接编译（未带 `-ldflags`）就可能出现这种情况。
* 使用项目提供的构建方式并指定版本即可避免：

  ```bash
  make V=1.0.0
  ```

* 版本未知时面板**不会误报有更新**，而是如实提示无法比较。

---

### 问题 11: 端口填了却提示无效 / 保存不了？
* 端口取值为 `0` 表示**禁用**该端口，是合法值。
* 非 0 的端口必须落在 **1025–65535** 之间（避免占用系统保留端口）。
* 各端口之间**不可重复**，重复时面板会拦截并提示。
* 如果某个端口被其它程序占用，内核启动会失败并给出提示，需先释放该端口。

---

### 问题 12: 反向代理后面板打不开、或路径不对？
* 确认反代已把请求转发到面板监听的 **Unix Socket**（默认 `app.sock`）或 TCP 地址。
* 若面板部署在子路径下（如 `/app/Fluxor`），需同时设置 `BASE_URL` 环境变量，使前端能正确拼接所有接口路径；设为 `/` 等同于根路径部署。
* 该配置在飞牛 OS 的应用网关中已由 `ui/config` 的 `gatewayPrefix` 自动处理，通常无需手动干预。

---

## 仍然无法解决？

请附上以下信息再提问，能显著加快定位速度：

1. 面板「日志」页面中相关的报错内容；
2. 运行数据目录（`FLUXOR_DATA_DIR`，飞牛 OS 默认 `/var/apps/Fluxor/var`）下的 `fluxor.log` 运行日志；
3. 面板版本与内核版本（「关于」面板中可查看）；
4. 您的部署方式（飞牛 OS 应用 / OpenWrt / 手动部署）。
